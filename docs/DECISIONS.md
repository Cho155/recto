# 决策记录

## 2026-11-02 · 立项

作者的要求：

- 审美借鉴 Anthropic 的简约风格，包括配色；一改普遍的极客风格；保留透明终端这类提升审美的设计。
- 图案使用线条画风格，不是简笔画；插画作为保留项。
- 可以借鉴 niri、Noctalia 等现有工具，也可以不用、换用其他工具或自行设计。
- 内存占用尽量低。
- 是开源项目，不只为作者当前的笔记本设计。
- 最终成品的样子在完成前难以描述，需要边做边看。

## 2026-11-02 · 作者的决定

- 本项目与作者此前的其他项目无关，不引用、不复用。
- **不允许在本机进行任何测试**（安装、构建、运行、修改本机配置都不做）。唯一允许测试的地方是作者提供的虚拟机；本轮不测试。虚拟机的登录信息只由作者在对话中提供，不写进仓库或任何记录。
- 设计上的选择交给助手决定。
- **界面语言默认英文**。其他语言的渲染由作者单独支持。

## 2026-11-03 · 作者：内存够了，转向审美

作者的判断：常见的极客桌面动辄占用 2 GB，Recto 现在约 150 MB，已经完全符合“简约”。整个会话只要在几百 MB 以内都可以接受。内存这么低，说明在视觉体验上还有很大的改进空间。下一阶段的重点是**审美优化**。

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D48 | 内存预算放宽：整个会话空闲 ≤ 400 MiB，外壳空闲 ≤ 100 MiB；仍然每次测量、留记录 | 作者确认几百 MB 以内都可以接受；保留明确的上限，免得不知不觉越涨越多 |
| D49 | 多出来的预算优先花在动效、材质和排版上，而不是往界面里加更多元素 | “安静”仍是第一原则：看起来更讲究，而不是更热闹 |

## 2026-11-03 · 审美优化：动效、材质、排版

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D50 | 外壳继续用 cairo 渲染器，动画也用它画 | 原计划为了动效换 GL（约多 24 MiB）。虚拟机实测，最大的今日页每帧绘制中位数 9.7 ms，帧间隔稳定在 13.3 ms（75 Hz 跑满）；GL 经 virgl 反而要 23 ms。高分屏像素是 4 倍，真机上要重测，掉帧时再换 GL（`GSK_RENDERER=gl` 即可，见 `reports/motion/`） |
| D51 | 面板的动效写成 CSS 关键帧：今日页和搜索从上方落下 8 px，音量提示从下方升起，通知从屏幕边缘滑入 24 px；离开时原路退回，更快 | 同一套令牌（`motion.travel`、`travel_side`、时长、缓动）生成全部关键帧；只用透明度和平移，不缩放，文字不会发虚 |
| D52 | 关闭面板时先交出键盘、停止接收点击，播完离开动画再销毁窗口（`motion.rs`） | 用户按 Esc 或从搜索打开应用时，键盘要立刻还给后面的窗口；但窗口本身要留到最后一帧，否则只能瞬间消失 |
| D53 | 每张通知卡片放在一个伸缩容器（GtkRevealer，SlideUp）里 | 新卡片插入、旧卡片离开时，其他卡片平滑让位，而不是跳动；SlideUp 让离开的卡片停在原地淡出，而不是被往上推走 |
| D54 | 窗口开合用 niri 26.04 的自定义着色器：开窗时从大 2% 落定并淡入，关窗时抬起淡出（`motion.window_lift`） | 像把一张纸放到桌上；niri 默认的开窗是从一半大小弹出，太活泼。着色器在合成器里运行，外壳不花内存 |
| D55 | 阴影分三档：静置的窗口、当前窗口与今日页（抬起）、小卡片；外壳的面板用两层阴影（贴近的接触线加柔和外扩），阴影由 CSS 画 | 焦点不只靠陶土色框表达，也靠高度；niri 的图层阴影不会跟着面板动画移动（虚拟机里看到阴影先于面板出现），所以今日页也改为自己画阴影 |
| D56 | 大号衬线字用 Source Serif 4 的光学尺寸：40 px 以上用 Display，16 px 以下用 SmText，都以普通 Source Serif 4 兜底 | 同一字体按字号分别设计的版本：大字号笔画更细、更挺，小字号更扎实。实测确认字重不变（静态字体没有 Medium，原来的 500 实际就落在 Regular 上） |
| D57 | 壁纸生成时加入极淡的纸纹（`wallpaper.grain`，正文色 4%），锁屏用同一张壁纸 | 生成一次后缓存，运行时零代价；锁屏像是把同一页纸盖住，而不是换了地方。面板不加纹理，保持干净 |
| D58 | 外壳的小图标（关闭、下拉、更多）改为 cairo 自绘，线宽来自令牌 `shape.icon_stroke` | 不依赖系统图标主题，每台机器上都一样；颜色跟随 CSS，悬停变色时自动重画 |
| D59 | 外壳启动的子进程设置 `PR_SET_PDEATHSIG`，随外壳一起结束 | 只在正常退出时清理不够：外壳被杀或合成器重启时，虚拟机里残留过 3 个 `pactl subscribe` |
| D60 | 面板销毁后调用一次 `malloc_trim` | 动画每帧都会申请大块的离屏缓冲，glibc 释放后不还给系统，关闭后外壳多占约 7 MiB；加上后降到约 4 MiB，而且反复开关不再增长 |
| D61 | “关闭面板后回落到空闲的 110% 以内”改为两条：首次打开留下的缓存 ≤ 5 MiB，反复开关 10 轮增长 ≤ 1 MiB | 实测关闭后为空闲的 117%（RSS 多 4.4 MiB），**旧标准没有达到**。逐个面板测量后发现，多出来的是第一次打开时加载的字体和样式缓存，之后不再增长（10 轮只多 0.2 MiB）。原标准想抓的是泄漏，新标准抓得更准 |
| D62 | 比较外壳内存时同时看 RSS | PSS 会把共享库平摊给所有使用者：昨天测量时 gnome-text-editor 开着，和外壳分摊 GTK 4，外壳的 PSS 因此少算约 6 MiB；RSS 两天都是 51 MiB 左右 |

## 2026-11-03 第二轮 · 作者：要古典，不要 Windows

作者：整个设计最终要更古典，而不是更像 Windows；借鉴 Anthropic 审美，就是为了像 Claude 区别于 Gemini 的炫酷那样，区别于现有桌面的极客风。壁纸的线条画由作者挑选。

第一轮的一部分改动（通知从边缘滑入 24 px、今日页和搜索的大阴影）正是浮动卡片界面的做法，这一轮一并收回。

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D63 | 界面借用书页和印刷的语汇：版心、细线、小型大写、旧体数字、衬线正文；不用大圆角卡片、大阴影、胶囊按钮、滑入横幅 | 作者的方向。“边注”“索引”“线条插画”本来就在理念里，这次让它们在界面上真正成立 |

| D101 | 开终端的快捷键改为 `footclient --no-wait \|\| foot`；`foot.ini` 改为按主题各生成一份（只差 `initial-color-theme`），`~/.config/foot/foot.ini` 经 `current` 链接 | 作者报告：关掉一个终端后会自动弹出一个 Paper 配色的终端。原因有两层：`footclient` 会等 shell 结束并带回它的退出码，关窗时 shell 被挂断、退出码不是 0，`\|\| foot` 就又开了一个独立的 foot；独立的 foot 只读 `foot.ini`，里面写死了默认主题（Paper），收不到登录时发给服务进程的信号（D34），所以 Ink 下也是纸色。`--no-wait` 让 footclient 连上服务就返回，只有连不上时才另开；另开的 foot 现在按当前主题启动。在测试机里复现了旧行为，并验证了关窗、shell 出错退出、服务不在三种情况 |
| D102 | 电量在状态栏常驻：日期左边一个次要色的百分比，插电时前面一道细线闪电；用电池且 ≤ 20% 时换成正文色并带剩余时间，≤ 10% 用陶土色。低电量不再作为按需提示出现 | 作者在笔记本上找不到电量，问“电量显示你做过吗”。原设计（只在低电量时出现，平时看今日页）对笔记本来说藏得太深；作者在两种方案里选了常驻。一个数字很安静，不违背“状态栏不放实时数字”的本意（那条针对 CPU、网速这类跳动的数据）。低电量由同一个数字变色表达，避免同一个百分比在栏上出现两次 |
| D103 | 快捷键的说明用 niri 自带的列表（Super+Shift+/），不做 Recto 自己的快捷键页；给列表里的每一项都写了 Recto 的说明（句子式大小写，和其他界面文字一致），补上全屏、按数字去工作区、截整屏／窗口、居中、标签等常用键，并在 README 加了一张完整的快捷键表 | 作者在三种方案（Recto 的快捷键页、页眉入口加 README、niri 自带）里选了 niri 自带。niri 默认的说明是标题式大小写（“Close Focused Window”），和 Recto 写的混在一起不统一；31 行在 1366×768 上放得下 |

## 2026-11-05 第三轮 · 网络、蓝牙、声音常驻；输入法候选框；更暖的纸

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| D104 | 状态栏常驻网络、蓝牙、声音三个细线标记（托盘箭头和电量之间），点一下或按 Super+N／Super+B／Super+S 在标记下打开文字列表；开关用 “On · Off” 两个斜体词，当前的带陶土色下划线；关闭的状态画一道斜线 | 作者要求这三样“尽量常驻，或者确认有对应的快捷键”，两样都做了。列表沿用托盘的纸条和键盘处理（D35、D79），开关沿用今日页的 “Paper · Ink · Auto”，不引入开关控件和卡片（D63–D72）。斜线而不只是变淡：Ink 的 `mark` 和 `muted` 是同一个颜色，单靠颜色看不出关闭。三个键原来都没被占用 |
| D105 | Wi‑Fi 直接走 NetworkManager 的 D-Bus（不调 nmcli）：列表读接入点和已保存连接；新网络用 `AddAndActivateConnection` 带上密码，连接失败就删掉刚建的连接；不注册密钥代理；企业网络和 WEP 交给 nm-connection-editor | 用 nmcli 时密码会出现在进程参数里，别的进程看得到；失败后删掉新连接，输错的密码就不会被保存、下次自动重试。作者的机器上没有 nm-applet，已有的连接（qyh、MyiPhone）都把密码存在系统里，所以不需要代理。测试机里用虚拟网卡验证了连接、断开、输错密码和开关；起初的 “Not authorized” 是从 SSH 启动外壳造成的，从 niri 启动就正常（niri 启动的外壳在当前登录会话里） |
| D106 | 蓝牙走 BlueZ 的 D-Bus：已配对设备按名字排序（连接状态变化时行不移动），“Find new devices” 搜索 30 秒，配对后设为信任再连接；不注册配对代理 | 测试时配对完成后列表按“已连接在前”重新排序，下一次点击落到了别的设备上，把耳机断开了，所以改成只按名字。没有代理时 BlueZ 用“无输入无输出”的方式配对，耳机、音箱、大多数鼠标可以；要输配对码的键盘做不了，列表里写 “Couldn’t pair”，用 bluetoothctl 或 blueman。测试机没有可用的蓝牙硬件，界面用假的 BlueZ 测过 |
| D107 | 声音走 `pactl`：列表读输出、输入和默认设备，`pactl subscribe` 的同一个子进程在设备变化时通知外壳（不再多开进程）；状态栏的 “Muted” 提示去掉，扬声器标记画叉代替；滑条原地更新，用手拖过后 0.9 秒内不被读回的值打断 | 和麦克风提示（D37）共用一个子进程，没有新的常驻开销。顺带解决了 D30 的一半：在别的程序里改音量，状态栏标记也会跟着变（音量提示仍然只在按键时弹出）。滑条如果每次读回都重设，拖动时会跳 |
| D108 | fcitx5 候选框做成 Recto 的两套主题 `recto-paper`、`recto-ink`：纸色底、细线边、Recto 的圆角，候选用衬线 Source Serif 4 12 pt（汉字经 fontconfig 落到 Noto Serif CJK SC），当前候选用选中文字的陶土色底；`classicui.conf` 设 `UseDarkTheme=True`；安装后用 fcitx5 的 `ReloadAddonConfig classicui` 让它重读 | 作者要求“输入法框可以加上 recto”。fcitx5 读门户的明暗设置，recto-theme 切换时本来就会改它，所以不需要额外的切换步骤（测试机里验证过 Paper→Ink 自动跟随）。`fcitx5-remote -r` 只重读输入法，不重读外观，测过不生效。用户以后在 fcitx5 的设置工具里改外观，它会把链接换成普通文件，下次安装时被改名备份 |
| D109 | Paper 的纸色更暖、略暗：底色 `#FAF9F5`→`#F7F2E7`，桌面 `#F0EEE6`→`#EDE6D7`，细线 `#E3E0D6`→`#DFD7C6`，以及 raised、backdrop、contour、plate_line、quiet、selection、veil 随之调整；次要色 `#6B6A65`→`#6A665E`；陶土文字色 `#B4532E`→`#B0512D`、终端亮黄 `#946B12`→`#8D6611`，把对比度拉回 4.5 以上 | 作者说“更暖的纸色是可以尝试的”，第一轮真机上也觉得纸色刺眼。只走一小步（亮度从 97% 降到 94%，色相从 48° 偏到 41°），全部文字颜色重新算过对比度，都不低于 4.5:1（两个本来就故意偏淡的终端色除外）。要换回去，用提交 `1d56fe0` 里 `design/tokens.toml` 的 `[theme.paper]` 和 `[theme.paper.ansi]` 两节替换现在的即可（`git show 1d56fe0:design/tokens.toml`）。已开的 foot 终端要等重新登录（foot 服务重启）才换上新纸色 |
