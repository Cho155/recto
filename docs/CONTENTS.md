## 为什么做

第一版排好了书的前后：扉页（锁屏）、今日页、索引（搜索）、页边纸条（通知）。但这些一天只看几十秒。窗口一打开，属于 Recto 的只剩页眉和一道陶土细线。第二版的主线是**排正文**：让 Recto 在工作时也在场。

目录页是其中的招牌：一页排好的目录，列出所有打开的窗口。它同时是窗口切换器，所以有实际用处；别的桌面没有这个画面，一张截图就能说明 Recto 是什么。

## 结构

| 书 | 桌面 |
| --- | --- |
| 章 | 工作区。章号是罗马数字（同状态栏，D65）；有名字的工作区排成 “I · Writing” |
| 条目 | 窗口。应用名用正体，窗口标题用斜体、次要色 |
| 页码 | 窗口所在的列号（niri 的 `pos_in_scrolling_layout`），旧体数字，右对齐，点线引过去 |
| 同一页上的几条 | 同一列里叠放的窗口：页码相同，按从上到下排 |
| 散页 | 浮动窗口：排在本章最后，没有页码 |
| 空白页 | 没有窗口的工作区，只在它是当前工作区时出现（和状态栏的规则一样），排一行斜体 “A blank page.” |

应用名取 .desktop 的 Name（搜索已经在读，`search::apps()`）；找不到时从 app id 推出来（`org.gnome.TextEditor` → “Text Editor”）。窗口标题末尾如果只是在重复应用名（“README.md — Text Editor”），去掉这一段。

## 交互

- **打开**：`Mod+Tab`（`recto-shell toggle-contents`，这个键位在 2026-11-04 的配置里是空的）。再按一次或 Esc 关闭。
- **不取代 niri 的总览**：总览留在 `Mod+O`，拖动整理窗口还要用它。目录页是“找到并翻过去”，总览是“摊开来整理”。
- **外观**：整页，写法同今日页（D69、D87）：一页不透明的纸盖住桌面，页眉保留；纸页一下子铺满，只有文字块淡入并落下 6 px。
  - 版心居中，宽约 560 px。顶上一行小型大写 “Contents”，下面一道细线。
  - 每章先排章名（小型大写、次要色），再排条目；章与章之间空一行半。
  - 条目一行：应用名、标题、点线、页码。标题太长时在中间省略，页码始终可见。
  - 所有章排完后，页尾一枚陶土色的常春藤花饰（❦），整页只此一枚。
- **记号**：打开时记号落在当前窗口那一行。记号所在的行用强调色的文字（Paper 下用 `accent_text`，因为 `accent` 在纸上对比度不够，见设计语言的用色规则）、应用名下一条细线。整页只有这一行和页尾的花饰是陶土色。
- **键盘**：↑↓（或 J／K、Ctrl+P／N）逐行移动，到头不回绕；Tab／Shift+Tab（或 Page Down／Up）跳到下一章、上一章的第一行；Enter 翻到那一页并关闭；Esc 关闭，不动。
- **鼠标**：点一行等于 Enter；点页边返回（同今日页，D85 的写法，注意别让文字块“认领”点击）。
- **实时**：页面开着时窗口有变化就重排。记号所在的窗口关掉了，记号回到当前窗口。
- **内存**：打开时创建，关闭即销毁；数据来自外壳已有的 `Desktop`（niri 事件流），不新增常驻的监听。应用名在打开时读一次。

## 决定（请接着 DECISIONS.md 的编号排）

| 决定 | 理由 |
| --- | --- |
| 第二版的主线是“排正文”，招牌是目录页 | 见“为什么做”。作者 2026-11-11 定 |
| 工作区是章、窗口是条目、页码是列号；同列共用页码；浮动窗口是散页，没有页码 | 列号是 niri 里窗口真实的位置，页码因此有用：看到 “3” 就知道它在第三列。浮动窗口不在任何一列里，硬编一个页码是假的 |
| 目录页不取代 niri 的总览，用 `Mod+Tab` 打开 | 两者做的事不一样，总览能拖动窗口；`Mod+Tab` 是别的系统里“切换窗口”的习惯键位，在 Recto 的配置里空着。助手提议，**待作者确认** |
| 永远不放窗口缩略图 | 缩略图是别的桌面的切换器；目录靠文字辨认，和“文字优先”一致 |
| 模型和视图分开：`contents.rs` 是纯数据，不依赖 GTK | 和 `state.rs` 同一个做法，可以单独测试；写它的时候也确实只能这样验证 |
| `state::Window` 多一个字段 `row`（列内从上到下的位置） | 同一列里叠放的窗口要按屏幕上的顺序排，之前只存了列号 |

## 已经写好的

- `shell/src/contents.rs`：
  - `chapters(desktop, output, name_of)` 把 `Desktop` 排成章和条目；
  - `Target`（一行通向哪里）和 `Target::action()`（对应的 niri 动作）；
  - `opening_target`、`step`、`step_chapter`：记号从哪里开始、逐行和逐章移动；
  - 10 个单元测试。
- `shell/src/state.rs`：`Window.row`。
- `shell/src/strings.rs`：`UNTITLED_WINDOW`、`chapter_heading`。
- `shell/src/main.rs`：`mod contents;`。

验证方式：没有 GTK 的环境，用一个只提供 `glib::DateTime` 的替身把 `state.rs`、`strings.rs`、`contents.rs` 三个真实文件一起编译，18 个测试通过（contents 新增的 10 个，state 原有的 7 个，strings 原有的 1 个），新代码没有警告。**整个外壳没有编译过**，请在测试机里跑一次 `cargo test`。

`contents.rs` 顶上有一行 `#![allow(dead_code)]`：视图写好之前没有人调用它，不加会有警告。接上视图后删掉。

niri 动作的 JSON 形状对照过 niri 主分支的 `niri-ipc/src/lib.rs`（`FocusWindow { id }`、`FocusWorkspace { reference: Id(u64) }`），没有在 niri 26.04 上实际发过，请在测试机里试一次。

## 待定（要看着实物定）

- **当前窗口和记号分开以后怎么标**：打开时两者重合。记号移走后，当前窗口那一行要不要留一个次要色的标记？两个候选：页码后一个斜体的 “here”；或者不标（页眉的列缩略已经说明了位置）。先做不标的，用起来觉得找不到再加。
- **散页的页码位置**放什么：空着，还是一个斜体的 “loose”。
- **状态栏上点工作区名**：现在是打开 niri 的总览。要不要改成打开目录页，作者定。
- **多显示器**：第一版只列当前屏幕的工作区。以后可以把每块屏幕排成一卷（Volume I、II）。
- **输入过滤**（边打字边筛条目）：第一版不做；目录通常不长，方向键够用。
- **点线在 1366×768 上的疏密**：太密像一条灰线，要在真机上看。
