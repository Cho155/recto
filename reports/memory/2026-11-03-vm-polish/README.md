# 内存测量 · 2026-11-03 · 审美优化之后 · 测试虚拟机

环境：测试虚拟机（Arch，内核 7.2.14，3 GiB 内存，3 核，virgl 显卡，1440×900，缩放 1）；niri 26.04、GTK 4.24.1、Pango 1.58.2、cairo 1.18.6、glibc 2.44。外壳用 cairo 渲染器（未设 `GSK_RENDERER`）。

这次的外壳加入了：面板动效（CSS 关键帧）、两层阴影、光学尺寸字体（Source Serif 4 Display / SmText）、自绘图标，以及关闭面板后的 `malloc_trim`（D60）。

测量时会话里开着一个 foot 终端；鼠标停在空白处（停在通知上会暂停它的倒计时，第一轮测量因此作废）。swayidle 在测试期间被手动停掉，避免中途锁屏（它常驻约 0.4 MiB，不在下面的合计里）。

### 为什么空闲的 PSS 比前一天高

前一天空闲为 18.5 MiB PSS，今天为 24.6 MiB；但 RSS 两天几乎相同（51.5 → 51.1 MiB）。

PSS 会把共享库平摊给所有使用它的进程。前一天测量时，gnome-text-editor 开着，和外壳分摊 GTK 4 的库；今天会话里只有外壳一个 GTK 4 进程。对照测试也排除了今天的改动：
- 换回前一天的样式表：24.6 MiB；
- 去掉 SmText 字体：24.7 MiB；
- 当前版本：24.5–24.8 MiB。

### 关闭后没有回到空闲值

- 关闭后比空闲多 4.1 MiB PSS（117%），**没有达到原来“110% 以内”的标准**。
- 没有加 `malloc_trim` 时多 7.1 MiB（129%）。
- 逐个面板打开再关闭，测得多出来的部分：

  | 步骤（MiB） | RSS | Pss_Anon | Pss_File |
  | --- | --- | --- | --- |
  | 空闲 | 51.2 | 8.5 | 16.0 |
  | 第一次开关今日页 | 55.1 | 11.4 | 16.7 |
  | 第二次开关今日页 | 53.4 | 9.7 | 16.7 |
  | 一条通知之后 | 53.6 | 9.9 | 16.7 |
  | 音量提示之后 | 55.1 | 11.4 | 16.7 |
  | 开关搜索两次之后 | 55.5 | 11.5 | 16.8 |

- 结论：多出来的是第一次打开面板时留下的缓存：文件页多 0.7 MiB（推测主要是第一次用到的字体文件，如 Display），匿名内存多约 3 MiB（样式、字形和分配器缓存）。之后不再增长。紧接着又把今日页、搜索、音量提示各开关 10 轮，RSS 只从 55.5 MiB 变为 55.7 MiB，PSS 从 28.6 MiB 变为 28.8 MiB。
- 因此把标准改为“首次缓存 ≤ 5 MiB，反复开关 10 轮增长 ≤ 1 MiB”（D61），两条都达到。

- 以下是上午的说明：niri 比前一天的 63.2 MiB 高。为了确认原因，在同一会话、同样两个窗口的条件下，把开窗着色器关掉再打开，各开关 3 次窗口后测量：开着色器 81.9 和 82.1 MiB，关着色器 81.9 和 82.1 MiB。着色器不占内存。差别更可能来自这次会话里大量的截图（screencopy）和反复开关窗口，下次要在刚登录的会话里重测。
- foot 比前一天高，是因为这次开着一个终端窗口（前一天的记录里没有）。
- swaybg 从 3.3 MiB 变为 4.0 MiB：壁纸加了纸纹之后 PNG 从 52 KB 变为 720 KB，但显示用的缓冲区大小不变。
- 测试过程中发现并修复：外壳被杀死或合成器重启时，`pactl subscribe` 会残留（今天的会话里攒了 3 个）。现在子进程设置了 `PR_SET_PDEATHSIG`，用 `kill -9` 结束外壳后，`pactl` 随之结束（D59）。
- 会话里有 4 个 `at-spi2-registryd`，每次重启 niri 会话多一个。这和留白无关，但值得以后查一下。
